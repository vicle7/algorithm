## Что такое структуры данных

**Динамический массив** — элементы лежат по индексам `0, 1, 2...`. В нашем учебном массиве заранее выделяется место, при переполнении ёмкость удваивается. Поэтому чтение по индексу — O(1), а вставка в середину требует сдвига — O(n).

**Связный список** — цепочка узлов, где каждый знает, кто идёт следующим. Чтобы добраться до индекса 5, обычно придётся пройти предыдущие 5 узлов. Зато в начало легко вставлять новый узел без сдвига других.

**Дек** (*double-ended queue*) — очередь с двумя концами. Можно добавить и удалить слева или справа за O(1). Реализация на двусвязном списке: каждый узел знает предыдущего и следующего.

**AVL-дерево** — дерево поиска, которое само корректирует форму поворотами. Слева меньшие ключи, справа большие, разница высот двух поддеревьев каждого узла не более 1. Поэтому поиск, вставка и удаление — O(log n). В этом проекте ключи — целые числа; повторы игнорируются. **Дерево ищет по значению ключа, а не по индексу:** обычного индекса в дереве нет.

## Основные операции `def`

| Структура | Взять по индексу | Найти значение | Вставить | Удалить |
|---|---|---|---|---|
| Динамический массив | `get(index)` | `find(value)` | `insert(index, value)` | `delete(index)` |
| Односвязный список | `get(index)` | `find(value)` | `insert(index, value)` | `delete(index)` |
| Дек | `get(index)` | `find(value)` | `insert(index, value)` / `appendleft` / `append` | `delete(index)` / `popleft` / `pop` |
| AVL-дерево | нет индекса | `search(key)` | `insert(key)` | `delete(key)` |

Для первых трёх структур `find` возвращает индекс **первого** совпадения или `-1`, если значение не найдено. `get` возвращает само значение. `delete(index)` удаляет элемент из структуры и возвращает его значение. При неверном индексе возникает `IndexError`. Индексация с нуля.

Пример:

```python
from data_structures import DynamicArray

numbers = DynamicArray([10, 20, 30])
numbers.insert(1, 15)        # [10, 15, 20, 30]
print(numbers.get(2))        # 20
print(numbers.find(30))      # 3
print(numbers.delete(0))     # 10
print(numbers.to_list())     # [15, 20, 30]
```

## Сложность операций

`n` — количество элементов, `O(1)` — время не зависит от `n`, `O(n)` — растёт примерно линейно, `O(log n)` — гораздо медленнее линейного, `O(n²)` — квадратично.

| Структура | Взять по индексу | Поиск значения | Вставка | Удаление |
|---|---|---|---|---|
| Динамический массив | O(1) | O(n) | в конец амортизированно O(1), в середину O(n) | O(n), в том числе в конце у нашей реализации цикл пуст, фактически O(1) |
| Связный список | O(n) | O(n) | в начало O(1), по произвольному индексу O(n) | из начала O(1), по произвольному индексу O(n) |
| Дек | O(n) | O(n) | на краях O(1), по произвольному индексу O(n) | на краях O(1), по произвольному индексу O(n) |
| AVL-дерево | нет индексов | O(log n) | O(log n) по ключу | O(log n) по ключу |

Динамический массив расширяет ёмкость с запасом, поэтому **средняя стоимость** добавления в конец O(1) даже несмотря на редкие дорогие расширения (амортизированная сложность). В списке `append` здесь O(n), поскольку мы не храним отдельный указатель на хвост.

## Две сортировки

```python
from sorting import bubble_sort, quick_sort

numbers = [4, 1, 3, 2]
print(bubble_sort(numbers))  # [1, 2, 3, 4]
print(quick_sort(numbers))   # [1, 2, 3, 4]
```

- **Пузырьковая:** сравнивает соседние элементы и меняет их местами, если стоят не по порядку. В худшем случае O(n²). В лучшем — O(n), поскольку есть ранняя остановка.
- **Быстрая:** выбирает опорный элемент, размещает меньшие элементы левее, большие правее, затем повторяет процедуру для частей массива. Среднее O(n log n), худшее O(n²) (например, на уже отсортированном массиве с выбором последнего опорного элемента).

Обе функции создают отсортированную **копию**, а переданный им список не изменяют.

## Отдельная задача TOML → JSON

`toml_task/example.toml`:

```toml
student = "Анна"
course = 2
scores = [5, 3, 4, 2, 5]
```

После команды `python -m toml_task.convert` получится `toml_task/result.json`:

```json
{
  "student": "Анна",
  "course": 2,
  "scores": [
    2,
    3,
    4,
    5,
    5
  ]
}
```

Программа проверяет наличие хотя бы 3 полей верхнего уровня и массива `scores`, сортирует его по возрастанию и сохраняет в JSON. Имя массива можно менять через `--array-field numbers`. Нужен Python 3.11+, потому что модуль `tomllib` появился в этой версии.

## Зачем нужны тесты

Тесты проверяют, что алгоритмы возвращают правильные значения. Например, после `insert(1, 15)` массив `[10, 20, 30]` должен стать `[10, 15, 20, 30]`. Кроме обычных случаев, есть тесты пустых структур, неправильных индексов, нескольких типов поворотов AVL, случайных операций и TOML-конвертации.

## Что такое CI и как получить GitHub-репозиторий

**CI** (Continuous Integration) — автоматический запуск проверок после изменений кода. Файл `.github/workflows/tests.yml` заставляет GitHub Actions запускать тесты на Python 3.11/3.12/3.13 после каждого `push` и для pull request.

1. Создай на github.com новый пустой репозиторий, например `algorithms-homework`. Лучше **не добавлять README** на сайте, так как он уже есть в проекте.
2. Открой терминал в этой папке и выполни команды ниже. Заменяй `YOUR_USERNAME` на свой логин GitHub.
3. После `git push` открой вкладку **Actions** в репозитории и дождись зелёной галочки у проверки `Python tests`.

```bash
git init
git add .
git commit -m "Implement data structures, sorting, tests and CI"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/algorithms-homework.git
git push -u origin main
```

Для отправки GitHub может попросить авторизоваться. **Архив ZIP — это исходники, не настоящий созданный репозиторий GitHub.** Его необходимо опубликовать самому.
